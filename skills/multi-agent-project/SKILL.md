# 多 Agent 專案協作工作流

本規範定義多個 AI agent 協作開發專案時的分工邊界、開工前規格關、監督與接手、異質審查及強制檢查機制。

## 三層分工

- **使用者（最上層）**：給目標、做決定、驗收；只在需要拍板或親手操作（輸入密碼、關閉程式、查看畫面）時被找。
- **主控（orchestrator）**：開工前拆解目標、切開檔案範圍、寫規格；收件時讀改動做最後驗收；方向錯誤時叫停。
- **整合者**：整合分支、合併主分支、commit、執行發布（只有這一層能動主分支與發布）。
- **施工／審查者**：依工作類型分流，在獨立 worktree／分支施工或獨立審查，不碰主分支。

各角色用途、工具限制、零依賴替代與「異質審查」原則，見 `references/roles-and-tools.md`。

## 先講好完成標準與開工前規格關

動手前先將工作分級（拿不準就當「中」；被要求「直接做」時，規格縮成主控自寫的範圍清單）：

| 級別 | 判斷條件 | 執行步驟 |
| --- | --- | --- |
| 小 | 單檔、行為已講清楚的小修（錯字、UI 小 bug、原因明確的測試失敗） | 跳過規格關，直接派工 |
| 中 | 跨檔、新增或改變既有行為、碰資料寫入／刪除／設定／額度、需求有模糊處 | 寫一頁規格 → 冷審 1 輪 → 有待決項目才問使用者 → 開工 |
| 大 | 新功能、架構調整、資料搬移、發布流程、重灌腳本 | 先反問前提 → 至少提兩個方案（必含最小改動）供選擇 → 寫規格 → 冷審最多 3 輪 → 核准後開工 |

- **硬閘**：中、大型工作在規格審過、待決項目有答案之前，不開工作分支、不派施工、不先搭架子。
- **不預設附和**：被問到是否擴大範圍，或發現提案做法不划算、複雜度大於效益時，直接說出判斷並明確建議不做或刪減。
- **先講好完成標準**：規格須寫明輸入／情境與對應的具體結果、不改的行為與完成條件，同時交給施工者與測試撰寫者。

規格格式見 `templates/spec.md`；規格冷審與問使用者的規則見 `references/delivery-and-review.md`。

## 派工設範圍與監督

- **範圍與單一負責人**：同一件工作只派給一人；派工單寫明只能修改的檔案清單與合理時限，做到一半不中途換人；方向錯了或問題已解時由上層叫停。
- **盯產出不盯狀態**：派完在背景跑盯下層的監看（沒有這工具時就定時看一次進度），觀察實際副作用（新 commit、改檔、進度檔、交件檔），不信「工作中」等狀態字；無變化且未超時則安靜不打擾。
- **停用檢查紅線**：任何檢查都不准停用或改成「失敗也照過」，要放寬門檻必須有驗證證據並由上層覆核。

卡住判斷、連敗先驗前提、中斷與接手規範見 `references/supervision.md`。

## 共用檔與資源防撞

- 上層派工時先切開各節點負責的檔案；必須動到共用檔前，先在任務看板登記（沒有這工具時就在 `TASKS.md` 登記），做完解除。
- 重工作（重編譯、完整驗收測試、發布、本機大模型評測）一律使用重工作排隊鎖（沒有這工具時就一次只跑一件），避免同時執行互撞。
- 本機模型資源依互動優先順序避讓，高優先級互動任務進行時暫停背景批次整理。

## 交件與收件

- 施工只在自己的 worktree／分支 commit；交件必附檔案清單、建議 commit 訊息、測試方式、未實測項目與測試副作用。
- 上層收件須真的讀改動（重點看是否會丟資料）並至少抽樣重跑一項驗證；有問題退回原對話補齊，不自己順手改。

完整交件規範、收件檢查表、出題規則與發布流程見 `references/delivery-and-review.md`。

## 審查（異質審查）

- **異質審查**：寫程式的人與審查的人必須使用不同家模型；審查進行中被審檔案不再更動。
- 審查只提供 diff、規格與檔案，不給作者結論；題目開頭一律貼入 `templates/review-header.md`。

審查題目組裝與第二家審查附加規則見 `templates/review-prompt.md`。

## 測試、權限安全與自動化

- **測試隔離與不可逆確認**：測試一律用暫存資料夾與測試設定，不碰正式資料、鑰匙圈或個人設定；刪除、覆蓋、改設定等不可逆操作須使用者本人確認；私人程式與紀錄不進公開免費池或未經核准的外部通道。
- **犯兩次的錯升級為強制檢查**：同類錯誤出現第二次時，依架構、型別／lint／hook／權限設定、驗收測試、文件順序往上一層固化，見 `references/repeat-mistakes.md`。
- **自動化入口閘與額度原則**：自動開工／放行前的雙問題檢查、預算上限與規則撰寫原則見 `references/automation-gate.md`。
