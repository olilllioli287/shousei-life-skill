# 犯兩次的錯升級成強制檢查

## 升級層級（由高到低）

同一類錯出現第二次，就不能只再寫一行規則。依序找最高一層能擋住的：

1. **架構讓它做不出來**：一個狀態一個主人、一件事一種做法、刪掉會被抄的舊寫法。
2. **型別、lint、hook、權限設定擋下**：錯誤訊息直接寫該用什麼。
3. **驗收測試測行為**：用測試驗證行為不退化。
4. **最後才寫文件或規則**：只給需要判斷的事（沒人照做也不會失敗）。

## 驗證、清理與定期掃描

- **驗證檢查有效**：新加的檢查要證明它抓得到過去那次真的錯（拿那次的版本跑一次會失敗）。
- **規則與強制機制對照表**：使用者糾正時，先修好這次，再查對照表；表上已有規則但沒有強制機制＝重犯，同一次改動就升級成更高一層。
- **清理冗餘文字規則**：某條規則已經由架構、型別、lint、hook 或權限設定擋住後，原本的文字規則刪掉、只留對照表那一列，省上下文與額度；刪除專案裡的規則檔或記憶裡的規則前先問使用者。只能靠判斷、沒辦法結構化的規則，放在顯眼位置並附一個真的失敗範例。
- **定期掃描**：每週一次交由大範圍讀檔模型或審查模型讀最近的 commit、回退、審查退件、記憶與使用者糾正，列出「出現兩次以上的錯誤類別＋證據＋建議擋在哪一層」，主控挑高頻的在任務看板開立任務（沒有這工具時寫進 `TASKS.md`）。
