# 監督、連敗驗證與中斷接手

## 監督與看產出判斷卡住

- 派完工作在背景跑盯下層的監看（沒有這工具時就定時看一次進度），不能等使用者詢問才發現卡住。
- 同一件工作只派給一個人。方向錯了或問題已解，上層主動叫停。
- 盯下層看實際副作用（新 commit、改檔、進度檔、交件檔），不信「工作中」這種狀態字；沒有變化就安靜，不去打擾。
- 派工時記下這類工作的合理時限；僅在下層報錯、開不了回合，或超過時限仍沒產出時才換人（不等舊的收完），其餘情況照「做到一半不中途換人」執行；下層在等回覆就直接回答解鎖。
- 任何檢查都不准停用或改成「失敗也照過」，要放寬門檻必須有驗證證據並由上層覆核。

## 連敗先驗前提

- 同一個方向的修法連續兩次過不了同一關，先停手，寫下這幾次修法共同假設的那一句前提，再找一個「前提錯了結果就會不同」的觀察去驗證它（也看失敗分布在哪，不只看失敗幅度）。
- 前提寫下並驗過之前，不准開始第三次修改。
- 上層收到「第二次還紅」的回報時，先要求提出前提與證據，不直接批准下一次修改。

## 中斷與接手

### 暫停

遇到需要暫停（闔蓋、登出、出門或上層叫停）時：

- 做完手上這一小步或退回去，不開新任務、叫停下層。
- 不做不可逆的動作（不 push、不發布）。
- 改到一半的檔案要留得住：獨立分支可 `wip:` commit，共用工作區就在進度檔寫清楚哪些檔改到一半。
- 在進度檔寫接手筆記：目標、做到哪、哪些已驗證、現在狀態、下一步第一個動作、關鍵檔、已知坑。
- 回報寫「這是暫停，不是完成」。若收到明確指示要求繼續做則不暫停。

### 接手

被中斷後回來，或交接後新開對話時：

- 先讀進度檔與交接檔，把前人紀錄當事實，不從頭重查、不重跑已經做完的重現或驗收測試；只比對「做完的 vs 還沒做的」找出接手點。
- 但前人宣稱「已通過／已修好」的項目，要在實際產物上對原始目標再驗一次才算數（自我回報不是證據）。
