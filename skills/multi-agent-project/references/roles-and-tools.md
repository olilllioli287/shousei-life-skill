# 角色對照表、異質審查與抽象工具

## 角色對照表

左邊先用，額度用完或不適合才往右（各角色不綁定特定模型名稱與額度數字）。

| 角色 | 適合做 | 限制與注意事項 |
| --- | --- | --- |
| 主控（orchestrator） | 拆解目標、切開檔案範圍、寫規格、最後驗收、與使用者對話 | 不跑批次、不常駐輪詢；日常監控交給盯下層的監看 |
| 整合者 | 整合分支、合併主分支、commit、執行發布（唯一能動主分支與發布） | 同時不宜開太多；不從頭寫大型功能 |
| 施工者（主力／備援） | 在獨立 worktree／分支寫程式、修 bug、整理交件清單 | 只能碰規格清單內的檔；無指令權限的沙盒施工者只改檔，編譯／跑測試／commit 交可執行指令的施工者或整合者 |
| 審查者（一審） | 審查 diff、對照規格、核對修正 | 只看材料不看作者結論；不派文字整理；注意異質審查 |
| 第二家審查（二審／關鍵三審） | 雙重確認；關鍵審查只留給搬移腳本、發布前、資料寫入邏輯 | 與一審不同家；僅在需要複審或高風險改動時使用 |
| 冷審者 | 開工前規格冷審、大範圍找檔 | 冷審時不給對話歷史與主控看法；找到的路徑要用腳本確認真的存在 |
| 測試撰寫者 | 依規格與原始需求產出驗收測試題目 | 不讀原始碼，不與寫程式者共用同一對話；若無寫檔權限則只輸出題目文字 |
| 便宜模型／本機模型／公開免費池 | 便宜模型：大範圍找檔、非敏感小改；本機模型：私人長檔摘要、資料不出電腦；公開免費池：公開資料翻譯與格式小改 | 私人程式與紀錄嚴禁進公開免費池；高優先級互動任務使用本機資源時，背景批次須避讓 |
| 長文研究用的模型 | 長篇技術調研、設計取捨並問、文件初稿 | 容易編造專案或網址，產出內容與題目須另外逐項核對 |

## 異質審查原則

- **寫與審不同家**：寫程式的模型與審查的模型必須來自不同模型家族（例如主力施工模型寫的程式，交給另一家審查模型審；備援模型寫的程式，再交給第三家或不同家模型審）。
- **設計取捨並問**：遇大型架構或設計取捨，可由兩家不同模型同題並問再比對（先附完整材料，不准掃整個專案）。

## 沙盒工具打包規範

若施工或審查模型在受限沙盒內（讀取工作區外檔案或執行指令會導致整輪失敗）：

- 先將要讀的檔案複製到暫存工作資料夾再執行。
- 讀檔任務題目開頭寫「不要執行任何指令，只用讀檔與列資料夾工具」。
- 上網查資料任務開頭寫「不要執行任何指令、不要讀本機檔案，只用上網工具」。

## 抽象工具與零依賴替代

- **任務看板**：放待辦、登記共用檔、記錄查到的事實與未決「提議」。沒有這工具時，在專案根目錄用 `TASKS.md` 維護。
- **盯下層的監看（watch-task）**：在背景盯下一層工作，只在完成、卡住、逾時才叫醒派工方。沒有這工具時，定時看一次進度或產出檔案變化。
- **重工作排隊鎖（heavy-lock）**：保護重編譯、完整驗收測試、發布、本機大模型評測，全機同一時間只跑一件、其餘排隊。沒有這工具時，一次只跑一件重工作，完成後再啟動下一件。
- **審查標頭組裝工具**：將審查態度、規則與回覆格式貼在審查題目開頭。沒有這工具時，直接複製 `templates/review-header.md` 貼在題目最前面。
