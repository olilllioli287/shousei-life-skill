# 自動化入口閘、規則撰寫與通用原則

## 自動化入口閘

- 讓 AI 自己開工或自己放行（自動發布、恢復工作自動繼續、排程派工、自動合併）之前先問兩題：
  1. 做錯了退得回嗎？
  2. 對不對能用程式驗嗎？
  任何一題答「不能」就不做全自動，改成停下等人確認。
- 每件自動化或長時間派工都要有預算上限（時間或額度，寫在派工單或排程裡），到了就停下回報，不自己延長。
- 第一次先親手做過或看它做過，再做成可重複的工具；逃生口（怎麼停、怎麼回復）要先寫好。

## 規則怎麼寫

- 規則只留會改變決定的句子，拿不準要不要留的就刪；事故經過（誰在哪天說了什麼、卡了什麼）放進記憶、任務看板或進度檔，不寫進規則檔。判斷型規則可以附一個「錯誤長什麼樣」的短例子。
- 換了主力模型就把規則檔重新檢查一輪；改了重要的規則，挑一兩件真實任務在改版前後各跑一次，看它有沒有讀到、行為有沒有變。

## 通用額度與安全紅線

- **不中途換人／換模型**：做到一半的工作不中途換人，主控也不中途換模型。
- **快重置額度利用**：有時間窗限制的額度快重置前，先拿去跑審查或批次，不用就浪費。
- **高成本發想模型**：僅在使用者同意與限時放行下用於發想、換角度審視，不跑批次、不讀程式。
- **私人資料**：私人程式碼與紀錄不進會留存提示詞或用於訓練的公開免費池；私人程式的批次小改交給私人工作區內的便宜模型或本機模型處理。
- **測試隔離**：測試一律用暫存資料夾與測試設定，不碰正式資料、鑰匙圈、使用者的個人設定。
- **不可逆確認**：刪除、覆蓋、改設定等不可逆操作，要使用者本人確認。
